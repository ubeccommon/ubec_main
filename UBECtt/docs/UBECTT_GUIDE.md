# UBECtt Token Creation Guide

## Overview
This guide will help you create the UBECtt token on the Stellar network.

## Prerequisites

1. **Install the Stellar SDK:**
   ```bash
   pip install stellar-sdk
   ```

2. **Have funded accounts:**
   - **Testnet:** Use the [Stellar Laboratory](https://laboratory.stellar.org/#account-creator) to create and fund test accounts
   - **Mainnet:** You need real XLM to fund your accounts (minimum ~2 XLM per account for base reserves)

## Understanding Stellar Token Creation

### Key Concepts

1. **Issuer Account**: The account that creates and issues the token. This account's public key becomes part of the token's identity.

2. **Distributor Account**: The account that initially receives the tokens from the issuer and can distribute them to others.

3. **Trustline**: Before any account can hold a custom token, they must create a trustline to that token's issuer. This is a security feature.

### The Process

1. **Create Trustline**: The distributor (or any receiving account) creates a trustline to the issuer for the UBECtt token
2. **Issue Tokens**: The issuer sends tokens to the distributor
3. **Distribute**: The distributor can now send tokens to other accounts (who must also create trustlines first)

## Using the Script

### Step 1: Prepare Your Accounts

**For Testnet (Recommended for testing):**
1. Go to https://laboratory.stellar.org/#account-creator
2. Click "Generate keypair" to create an issuer account
3. Save both the Public and Secret keys securely
4. Click "Fund account with Friendbot" to get test XLM
5. Repeat for a distributor account (or let the script generate one)

**For Mainnet:**
- Create accounts using a Stellar wallet
- Fund them with real XLM (you'll need at least 2 XLM per account plus transaction fees)

### Step 2: Run the Script

```bash
python create_ubectt_token.py
```

The script will prompt you for:
1. Your issuer account's secret key
2. Whether you have an existing distributor account (or it will create one)

### Step 3: Save Important Information

After successful creation, save:
- Token Code: `UBECtt`
- Issuer Public Key: (provided in output)
- Distributor Public Key: (provided in output)
- Distributor Secret Key: (IF generated by script - CRITICAL!)

## Important Notes

### Token Limits and Control

- **Supply Control**: To limit the total supply, you can lock the issuer account after minting
- **Revocability**: Set authorization flags if you want to control who can hold the token
- **Metadata**: Add a home domain and TOML file for token information

### Security Best Practices

1. **Never share secret keys**: Keep them encrypted and secure
2. **Use hardware wallets**: For mainnet issuer accounts
3. **Test on testnet first**: Always test the complete flow on testnet
4. **Backup keys**: Store backups in multiple secure locations
5. **Set up authorization**: Consider using Stellar's authorization flags for regulatory compliance

### Common Issues

**"Account not found"**: 
- Make sure the account exists and is funded with XLM
- On testnet, use Friendbot to fund accounts
- On mainnet, send at least 2 XLM to the account

**"Transaction failed"**:
- Check you have enough XLM for fees (0.00001 XLM per operation typically)
- Verify you're connected to the correct network (testnet vs mainnet)

**"Trustline creation failed"**:
- Ensure the distributor account is funded
- Check that the asset code is correct (max 12 characters)

## Next Steps After Token Creation

### 1. Set Up Token Information

Create a `stellar.toml` file and host it on your domain:

```toml
[DOCUMENTATION]
ORG_NAME = "Your Organization"
ORG_URL = "https://yourwebsite.com"

[[CURRENCIES]]
code = "UBECtt"
issuer = "YOUR_ISSUER_PUBLIC_KEY"
display_decimals = 7
name = "UBECtt Token"
desc = "Description of your token"
```

### 2. Set the Home Domain

Link your issuer account to your domain (requires additional transaction).

### 3. Consider Token Authorization

You can set flags on your issuer account:
- `AUTHORIZATION_REQUIRED`: Accounts need approval to hold your token
- `AUTHORIZATION_REVOCABLE`: You can revoke token holdings
- `AUTHORIZATION_IMMUTABLE`: Authorization settings cannot be changed

### 4. Lock the Issuer (Optional)

If you want a fixed supply:
1. Issue all tokens you'll ever need
2. Lock the issuer account by setting its master weight to 0

## Distribution Strategy

To distribute tokens to users:
1. Users create trustlines to your token
2. You (from distributor account) send tokens to users
3. Consider creating a web interface for token claims
